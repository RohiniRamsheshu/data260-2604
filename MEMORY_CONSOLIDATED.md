# Consolidated Memory

1. The user is studying DATA-260 and building HW6.
2. The project uses FastAPI, Uvicorn, MongoDB, and Ollama.
3. The local Ollama model is qwen2.5:3b.
4. The user prefers simple explanations with enough detail to understand concepts.
5. The user also wants interview-oriented explanations.
6. MongoDB stores messages, summaries, and durable episodes.
7. Ollama is stateless between requests.
8. The application retrieves memory from MongoDB and adds it to the prompt.
9. Recent memory uses a configurable window.
10. The current experiment compares windows of 4, 12, and 30 messages.
11. Summaries are created every five user messages.
12. Prompt tokens are sent to the model.
13. Response tokens are generated by the model.
14. Latency measures response time.
15. Larger prompts can increase token usage and cost.
16. Compression can reduce prompt size while preserving useful context.
17. Postman is used for API testing.
18. Screenshots are stored in reports/hw06/screenshots.
19. Raw experiment results are stored in reports/hw06/raw.
20. The final report is a PDF.
21. The project should use small, testable functions.
22. Input should be validated before database operations.
23. Errors should be reported clearly.
24. Results should be verified before being reported.
25. MongoDB provides structured, persistent runtime memory.
26. File memory provides portable, human-readable project context.
